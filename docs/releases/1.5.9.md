# 1.5.9：UDP 大报文完整性与队列内存优化

本版本修复默认配置下超过 8192 字节的 UDP 报文被截断的问题，并降低小报文
在转发队列中的内存占用。

## 变更

- 面板创建、更新转发时显式下发 64 KiB UDP 接收缓冲区。参数采用字符串
  形式，兼容旧节点的 JSON metadata 解析。
- 节点默认 UDP 接收缓冲区从 8 KiB 调整为 64 KiB，升级重启后，原有未显式
  配置缓冲区的转发也能完整接收大报文。
- 小报文按缓冲池大小档位入队，接收缓冲区复用；已需要大缓冲区的报文直接
  移交，避免无收益的复制。
- 连接关闭时回收未消费的报文，阻止关闭后继续入队，并处理监听器并发关闭。

## 升级

建议面板与节点一起升级到 `1.5.9`。仅更新面板不会自动调整已经运行的节点
监听器；节点升级重启后，旧配置会使用新的默认接收容量。显式配置过较小
缓冲区的节点需单独检查。

节点重启或转发服务重新下发会重建相关连接，请安排合适的升级时间。
具体配置和兼容性说明见附件 `udp-forwarding.md`。

## 验证与影响

- 本地单节点、TCP 隧道、TLS 多跳均通过 9000 字节报文完整性验证。
- 三种模式各完成 64 个客户端、3200 次收发，共 9600 次检查未出现超时或
  内容不匹配；Go 并发检测和回归检查通过。
- 1200 字节报文排满单个 128 包队列时，排队缓冲区从约 8 MiB 降至 256 KiB。
  该数字不包含连接和运行时开销。
- 本地队列基准中小报文耗时基本持平，9000/65507 字节报文耗时分别增加约
  9%/6%；实际性能取决于工作负载。详细测量条件见附件。

当前面板诊断仍使用 TCP 探测，不能据此确认 UDP 可达性。公网丢包、限速和
长期高负载需在实际部署环境验证。
